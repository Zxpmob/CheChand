# چی چند — سایت قیمت طلا، ارز، سکه و رمزارز

یک سایت استاتیک (بدون نیاز به سرور/بک‌اند) با طراحی شیشه‌ای (liquid glass)
و تم طلایی که خودش را با تنظیمات دستگاه کاربر (روشن/تیره) هماهنگ می‌کند.
برای آپلود مستقیم روی **GitHub Pages** آماده است.

> **نسخه‌ی بدون پوشه:** همه‌ی ۲۵ فایل این نسخه (HTML، CSS، JS) در یک سطح
> و بدون هیچ زیرپوشه‌ای هستند، دقیقاً برای این‌که بتوانید همه را یک‌جا و
> بدون نگرانی از ساختن پوشه، مستقیم توی ریشه‌ی ریپازیتوری آپلود کنید.

## ۱) درباره‌ی منابع قیمت (این بخش را حتماً بخوانید)

### الف) طلا، نقره، سکه، ارز
این نسخه اول از یک **وب‌سرویس رایگان و کاملاً بدون کلید** BrsApi استفاده
می‌کند (`Api_Free_Gold_Currency_v2.json`). یعنی از همان لحظه‌ی آپلود، بدون
هیچ تنظیمی، باید قیمت‌ها نمایش داده شوند. کلید رایگانی هم که قبلاً دادید
(`BRSAPI_KEY` در `data.js`) به‌عنوان پشتیبان نگه‌داشته شده — اگر منبع
اصلی برای هر دلیلی در دسترس نبود، سایت خودش سراغ نسخه‌ی کلیددار می‌رود.

**مهم:** چون از اینجا (محیط ساخت سایت) اجازه‌ی دسترسی خودکار به داده‌های
خام BrsApi را نداشتم، ساختار دقیق JSON را ندیده‌ام؛ `data.js` طوری نوشته
شده که با اسم‌های رایج (`name`, `name_en`, `price`, `change_percent` و…)
در هر عمقی از JSON کار کند. بعد از آپلود، سایت را باز کنید و کنسول
مرورگر (F12 → Console) را نگاه کنید:
- اگر قیمت‌ها نمایش داده شدند، همه‌چیز مرتب است. ✅
- اگر نه، یک بار این آدرس را مستقیم توی مرورگرتان باز کنید:
  `https://BrsApi.ir/FreeTsetmcBourseApi/Api_Free_Gold_Currency_v2.json`
  و متن JSON خروجی را برایم بفرستید تا نام دقیق فیلدها را در تابع
  `applyBrsApi()` داخل `data.js` تنظیم کنم.

### ب) رمزارز — همه‌ی بازار، به‌صورت خودکار
دیگر لیست ثابتی از رمزارزها در کد نیست؛ سایت هر ۶۰ ثانیه **۱۰۰ رمزارز
برتر بازار** (بر اساس ارزش بازار) را مستقیم از CoinGecko (رایگان، بدون
کلید) می‌گیرد و در صفحه‌ی «ارز دیجیتال» نشان می‌دهد. اگر خواستید بیشتر از
۱۰۰ تا نشان داده شود، در `data.js` مقدار `CONFIG.CRYPTO_PAGES` و آدرس
`page=` در تابع `fetchCoinGeckoMarkets()` را افزایش دهید (هر صفحه ۱۰۰
رمزارز اضافه می‌کند).

### ج) دسته‌های «فلزات صنعتی، سنگ قیمتی، خودرو، کلکسیونی» حذف شدند
برای این چهار دسته هیچ API رایگان و معتبر ایرانی پیدا نکردم که بشود با
اطمینان بهشان وصل شد، برای همین به‌جای نمایش قیمت‌های ثابت/تقریبی که ممکن
بود گمراه‌کننده باشند، کامل از سایت حذفشان کردم. سایت الان فقط پنج دسته‌ای
را نشان می‌دهد که یک منبع قیمت لحظه‌ای واقعی دارند: **طلا، نقره، سکه، ارز،
ارز دیجیتال**.

اگر خودتان یک API (رایگان یا پولی) برای هرکدام از آن دسته‌ها پیدا کردید،
پایین همین فایل راهنمای کامل «اضافه‌کردن یک دسته‌ی جدید» را دارید.

### د) نمودار طلا و تاریخچه‌ی واقعی — همین‌جا از Supabase هم می‌گویم
نمودار طلای صفحه‌ی اصلی، قیمت‌های واقعی را همان لحظه که سایت باز است ثبت
می‌کند (در `localStorage` مرورگر خود شما) — یعنی کاملاً واقعی است، ولی
تاریخچه‌اش فقط از «الان به بعد» شروع می‌شود و بین دستگاه‌های مختلف/کاربران
مختلف مشترک نیست.

اگر یک نمودار تاریخی واقعی (مثلاً روند ۳۰ روز گذشته، برای همه‌ی
بازدیدکننده‌ها یکسان) می‌خواهید، به یک پایگاه‌داده‌ی کوچک نیاز دارید که هر
بار قیمت‌ها را ذخیره کند. **Supabase** برای همین کار عالی و رایگان است:
1. یک پروژه‌ی رایگان در [supabase.com](https://supabase.com) بسازید.
2. یک جدول به اسم مثلاً `price_history` با ستون‌های `item_id` (متن)،
   `price` (عدد) و `created_at` (تاریخ، پیش‌فرض `now()`) بسازید.
3. از **Settings → API** دو مقدار را برایم بفرستید: `Project URL` و
   `anon public key`.
4. من کد لازم را برای «هر بار که قیمت جدید آمد، یک ردیف در Supabase ذخیره
   شود» و «نمودار از Supabase (نه فقط از مرورگر خودتان) بخواند» به سایت
   اضافه می‌کنم — تا نمودار برای همه یکسان و واقعاً تاریخی شود.

فعلاً اگر این کار را نکنید، سایت کاملاً کار می‌کند، فقط نمودار طلا تا
مدتی که بازش نگه دارید ساخته می‌شود، نه بیشتر.

## ۲) آپلود روی GitHub Pages

1. یک ریپازیتوری جدید در گیت‌هاب بسازید (مثلاً `chechand`).
2. تمام فایل‌ها (۲۵ فایل، بدون هیچ پوشه‌ای) را یک‌جا آپلود کنید — همه‌ی
   `.html` ها، `.js` ها، `style.css` و بقیه، مستقیم توی ریشه‌ی ریپازیتوری.
   نیازی به ساختن هیچ پوشه‌ای نیست، چون این نسخه کاملاً «flat» (بدون
   پوشه) است.
3. در تنظیمات ریپازیتوری: **Settings → Pages → Branch: main / (root)**
   را انتخاب و ذخیره کنید.
4. بعد از چند دقیقه سایت روی آدرسی مثل
   `https://USERNAME.github.io/chechand/` بالا می‌آید.

### اگر دامنه‌ی اختصاصی دارید
یک فایل به اسم `CNAME` (بدون پسوند) با محتوای دامنه‌تان (مثلاً
`nerkhlahze.ir`) در ریشه‌ی پروژه اضافه کنید و در تنظیمات DNS دامنه یک
رکورد CNAME به `USERNAME.github.io` بزنید.

### آدرس واقعی سایت را جایگزین کنید
در فایل‌های `sitemap.xml`، `robots.txt` و تگ‌های `canonical`/`schema` در
هر صفحه، آدرس فرضی `https://example.com` گذاشته شده؛ بعد از مشخص‌شدن
آدرس نهایی سایت، یک جست‌وجو-و-جایگزینی (Find & Replace) روی همه‌ی فایل‌های
`.html` و `sitemap.xml`/`robots.txt` انجام دهید و آن را با دامنه‌ی واقعی‌تان
عوض کنید.

## ۳) اضافه‌کردن یک دسته‌ی جدید (مثلاً فلزات صنعتی، سنگ قیمتی، خودرو، کلکسیونی…)

سایت طوری طراحی شده که اضافه‌کردن یک دسته‌ی جدید — به شرطی که یک API برایش
پیدا کنید — فقط با ویرایش چند فایل انجام می‌شود، بدون نیاز به تغییر طراحی
یا ساختار سایت. مراحل را با یک مثال («فلزات صنعتی») توضیح می‌دهم:

**گام ۱ — یک API برای دسته‌ی جدید پیدا کنید**
یک وب‌سرویس رایگان یا ارزان پیدا کنید که خروجی JSON بدهد (اکثر APIهای
قیمت همین‌طورند). آدرس، پارامترها و — اگر لازم بود — کلید API را یادداشت
کنید.

**گام ۲ — آیتم‌های دسته‌ی جدید را در `items.js` تعریف کنید**
داخل آرایه‌ی `SITE_ITEMS`، قبل از خط `];` چند خط مثل این اضافه کنید:
```js
// ---------------- فلزات صنعتی ----------------
{ id: "platinum", cat: "metal", name: "پلاتین", unit: "دلار / انس", source: "manual" },
{ id: "copper",   cat: "metal", name: "مس",      unit: "دلار / تن",  source: "manual" },
```
- `id` باید یکتا باشد (در کل فایل تکراری نباشد).
- `cat` اسم دسته‌ی جدید است؛ خودتان انتخاب می‌کنید (مثلاً `"metal"`).
- فعلاً `source: "manual"` بگذارید تا در گام بعد به API واقعی وصلش کنیم.

سپس در همان فایل، داخل آرایه‌ی `SITE_CATEGORIES` یک خط اضافه کنید:
```js
{ id: "metal", title: "فلزات صنعتی", page: "metals.html", icon: "metal" },
```
(آیکن‌های آماده در `components.js` داخل شیء `ICONS.cat` هستند:
`gold, silver, coin, currency, crypto, metal, gem, car, collectible` — همه از قبل رسم شده‌اند.)

**گام ۳ — یک تابع fetch در `data.js` بنویسید**
همان الگوی تابع `fetchCoinGecko()` / `applyCoinGecko()` را کپی کنید،
اسم و آدرس API را عوض کنید، و در تابع `refreshAllPrices()` صدایش بزنید:
```js
async function fetchMetalsApi() {
  try {
    const res = await fetch("https://ADDRESS-OF-YOUR-API");
    if (!res.ok) throw new Error("HTTP " + res.status);
    return await res.json();
  } catch (err) { console.error(err); return null; }
}
function applyMetalsApi(raw) {
  if (!raw) return;
  // اینجا هر فیلدی که API برگرداند را به setPrice() بدهید، مثلاً:
  setPrice("platinum", { price: raw.platinum.usd, changePercent: raw.platinum.change, unit: "دلار / انس", cat: "metal", updated: Date.now() });
}
```
و داخل `refreshAllPrices()`:
```js
const [brs, cg, metals] = await Promise.all([fetchBrsApi(), fetchCoinGecko(), fetchMetalsApi()]);
applyBrsApi(brs); applyCoinGecko(cg); applyMetalsApi(metals);
```

**گام ۴ — یک صفحه‌ی HTML برای دسته‌ی جدید بسازید**
ساده‌ترین راه: یکی از فایل‌های موجود مثل `silver.html` را کپی کنید، اسمش
را به `metals.html` تغییر دهید و داخل فایل این‌ها را عوض کنید:
- `<title>` و `meta description`
- متن `<h1>` و پاراگراف زیرش
- خط `wireLiveGrid("cat-grid-silver", "silver");` را به
  `wireLiveGrid("cat-grid-metal", "metal");` تغییر دهید (و `id` باکس
  `<div id="cat-grid-silver">` را هم هماهنگ کنید).
- در انتهای فایل، مقدار `renderHeader("silver.html")` را به
  `renderHeader("metals.html")` تغییر دهید.

**گام ۵ — لینک صفحه‌ی جدید را جایی از سایت بگذارید**
مثلاً یک خط در `main-nav` (داخل `components.js`) یا فقط از طریق
داشبورد/جستجو در دسترس باشد — چون `SITE_CATEGORIES` را در گام ۲ آپدیت
کردید، صفحه‌ی اصلی و جدول «همه‌ی قیمت‌ها» و جستجو خودشان دسته‌ی جدید را
نشان می‌دهند.

**گام ۶ — `sitemap.xml` را آپدیت کنید**
یک خط جدید مثل بقیه اضافه کنید:
```xml
<url><loc>https://YOURDOMAIN/metals.html</loc><changefreq>hourly</changefreq><priority>0.7</priority></url>
```

## ۴) درباره‌ی «اول‌شدن در گوگل»

نکته‌ی صادقانه: هیچ کدی نمی‌تواند تضمین کند یک سایت برای هر کلمه‌ای اول
نتایج گوگل بشود — رتبه به کیفیت محتوا، تعداد و اعتبار بک‌لینک‌ها، سرعت
سایت، و رقابت آن کلمه در طول زمان بستگی دارد، نه فقط کدنویسی. کاری که در
این پروژه از نظر سئوی فنی انجام شده:
- هر صفحه عنوان، توضیحات (`meta description`) و آدرس canonical مخصوص به
  خودش را دارد.
- `sitemap.xml` و `robots.txt` آماده و کامل است.
- دیتای ساخت‌یافته (`JSON-LD`) روی صفحه‌ی اصلی برای قابلیت جستجوی سایت.
- ساختار HTML معنایی (heading ها، لینک‌های داخلی بین صفحات) و سایتی
  کاملاً استاتیک و سریع (بدون فریمورک سنگین).
- صفحه‌ی جستجوی داخلی (`search.html`) که همه‌ی اصطلاحات بازار را پوشش
  می‌دهد.

برای رتبه‌گرفتن واقعی، بعد از انتشار: سایت را در
[Google Search Console](https://search.google.com/search-console) ثبت
کنید، نقشه‌سایت را معرفی کنید، و به‌مرور محتوای متنی (مثلاً توضیح هر
دسته، مقاله‌های کوتاه بازار) اضافه کنید.

## ۶) محدودیت‌های مهمی که باید بدانید

- چون سایت کاملاً استاتیک است (بدون سرور)، هشدار قیمت فقط وقتی کار
  می‌کند که تب سایت باز باشد؛ برای هشدار پیامکی/ایمیلی واقعی به یک سرویس
  بک‌اند (مثلاً یک Cloudflare Worker یا Firebase Function رایگان) نیاز
  دارید که در این نسخه پیاده نشده.
- نمودار روند («تاریخچه») از لحظه‌ای که کاربر برای اولین‌بار صفحه را باز
  می‌کند در همان مرورگر ساخته می‌شود (چون سایت سرور و دیتابیس ندارد)؛ برای
  نمودار تاریخی واقعی (هفتگی/ماهانه) باید به یک API که تاریخچه می‌دهد وصل
  شوید.
- لیست علاقه‌مندی‌ها و هشدارها در `localStorage` مرورگر کاربر ذخیره
  می‌شود، نه در یک حساب کاربری — یعنی بین دستگاه‌های مختلف همگام نیست.
